  alias、shape/numel、dtype/device、optimizer group、实际 learning rate/weight decay、
  模块标签和状态序列化边界；清单和异常输入必须 fail-closed。

## 已完成的实现

1. `core.registry.ParameterRegistry`
   - 以 alias 集合的字典序最小名称作为 canonical name，并对独立参数排序，
     不受模型参数注册顺序影响。
   - 共享 `Parameter` 只生成一个坐标；不同对象的重叠 storage、sparse 参数/梯度、
     optimizer 跨组重复和未知参数均拒绝。
   - 记录 `shape`、`numel`、连续 `order`、eligibility 原因、group、dtype/device/layout/stride、
     learning rate、weight decay，以及 embedding/attention/MLP/norm/head 等保守标签。
   - 增加 registry manifest v1 的严格生成、保存、加载、hash 核对和与当前模型/optimizer
     的绑定校验；实际学习率/weight decay 映射漂移会被拒绝。
   - 增加 expected-vs-abnormal `grad is None` 分类；异常缺梯度不再静默补零。
2. `core.state.ImportanceState`
   - 提供 FP32/FP64 的 S1/S2 临时工作区、signed/positive/negative_mass/absolute、raw、
     data/net movement、magnitude，以及可选 `actual_update_raw_importance` 命名空间。
   - slot 必须覆盖完整 eligible registry，严格核对 registry hash、shape、dtype、有限性；
     临时状态可清零复用，长期状态只能在显式完整 optimizer step 后原子提交。
   - 使用既有 `runtime.tensor-bundle.v1` raw tensor codec 保存/回载，未引入 pickle。
3. `stage1_manifest`
   - 将文件读取、严格 JSON 解析、Stage 0 asset manifest 合同校验、revision/files 期望校验、
     可选物理文件 size/SHA-256 校验分层。
   - 接受 UTF-8 和 UTF-8 BOM；未知编码、重复键、非有限数、字段/类型/hash/替代文件异常
     均以结构化 Stage 1 manifest 错误拒绝。
4. Schema、测试和 task runner
   - 新增 parameter registry、importance state、G1-REGISTRY report 的 JSON Schema。
   - Stage 1.02 runner 现在输出完整 registry manifest、state schema 和机器可读的本地校验
     投影；formal G1-REGISTRY 仍明确标为 `NOT_RUN`，没有把 CPU fixture 冒充正式 Gate。
   - 新增 S1.2 行为测试，覆盖顺序稳定、alias、冻结参数、缺梯度、manifest/hash、shape/LR
     漂移、状态 bundle、BOM/编码/files/size-hash 分支。
