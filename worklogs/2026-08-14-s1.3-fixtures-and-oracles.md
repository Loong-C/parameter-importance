# S1.3：确定性 fixture 与独立 oracle

## 任务边界

- 任务：`stage1.03_fixtures_and_oracles`。
- 依赖：S1.1 的 `G1-ENTRY`、`G1-CONTRACT`，以及 S1.2 的 `G1-REGISTRY` 正式结果。
- 本次目标：冻结可序列化的 Stage 1 fixture，建立不调用生产 estimator kernel 的 FP64
  独立 oracle，覆盖解析梯度、解析/自动微分/有限差分、Tiny Transformer 样本与
  microbatch 梯度、路径求积、SGD decay 分解、M=1/负 U/权重/排列和零均值噪声边界，
  并发布可离线 replay 的 `G1-ORACLE` 证据。
- Pythia-14M 在本任务只登记固定 descriptor；真实模型/数据链路留给 S1.7，不能由本
  任务的本地 fixture 解锁或冒充。

## 已完成的实现

1. `fixtures/stage1/stage1-s13-v1.json`
   - 冻结 `zero/equal/negative/varied/M=1` 梯度矩阵、坐标 shape、非均匀外生权重和
     sample purpose。
   - 冻结 FP64 analytic quadratic/constant path、有限差分步长、已知 SGD learning
     rate/weight decay 分解。
   - 冻结无 dropout 的 Tiny causal Transformer、seed、token/mask、sample ID、
     microbatch 分组、valid-token 边界，并绑定 `coordinate_registry_hash` 与
     `initial_state_hash`。
   - 冻结两组多次重复的零均值 Gaussian noise property fixture，以及 Pythia step-0
     revision `56079904bb80b7f36d3b794089f146e7a4d6efae` descriptor。
   - manifest 自身 hash：`4ed40875eefb15f5fdb4a4acc1386a69130f9e3bdccbb9e5af90e60c40cb5dac`。
2. `src/param_importance_nlp/stage1_fixtures.py`
   - 以显式 FP64 Python loops 生成 mean/raw/U/weighted-U；模块不导入
     `core.estimators`，oracle bundle 标明 `formal_estimator_imported=false`。
   - Tiny Transformer 初始化使用 seed 参与的显式算术填充，不依赖跨 PyTorch 版本可能
     变化的 RNG initializer；因此本机与服务器初始 state hash 一致。
   - 输出 `fixture_manifest`、`oracle_bundle`、`oracle_validation_report` 三个不同
     角色，均以 hash 绑定；保存后的 bundle 可在不采样、不启动训练循环的情况下 replay。
3. runner/schema/formal 入口
   - S1.3 task runner 不再把同一小样本 payload 复制到三个 artifact；每个 artifact
     的 `core_evidence_hash` 绑定其角色内容。
   - 新增 fixture、oracle bundle、validation report、formal index/validation schemas。
   - `ops/stage1/formalize_s1_3.py` 先校验 S1.2 immutable handoff，再执行 server CPU
     regression、direct checks、canonical roundtrip 和 offline replay，最后原子发布
     新 attempt。
   - `generate_cpu_evidence.py` 现在拒绝覆盖已有 evidence 目录，要求新 suffix。
